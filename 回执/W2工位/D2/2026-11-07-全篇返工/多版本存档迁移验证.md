# 多版本存档迁移验证

2026-11-07，D2 场景交互工位。代码已交主工位，最终判过由 D4 负责。此补充没有清理玩家数据，也没有另行出包或导入素材。

## 原因与方法

原迁移表只覆盖早期基线，042c367 候选版的来电 24 拍、静冈 20 拍、香港 15 拍签名不在表内。本轮增加步骤后，旧签名会触发整场重来。

`scene_migrations.json` 保留原基线，并增加 `_versions` 保存从 `git show 042c367:godot/hongyuan/chapters/...` 提取的完整 beats。三个版本分别为 24 / 20 / 15 拍，已逐对象与 Git 内容核对一致。读取时先匹配完整 JSON 签名，再解释旧拍号；不对未知签名猜测。

匹配后的迁移按语义映射：游戏以 game 键及同类出现顺序匹配，对白以 copy ID 匹配，当前行也按 copy ID 重映射。旧香港 photo 对应当前第一张合影，不映射到新增的城堡或校园 photo。背景/隐藏等设置拍定位到后续语义入口；只有相同活动才保留游戏内部状态，不把旧 phase 交给另一个游戏。

新增必做步骤的处理：

- 旧来电进度已经过关心/日常互动新增位置时，回到 care 前的说明入口，随后完成 care 与 balance。
- 旧静冈领证旁白或印章奖励处，进入新增 registration，随后在双人持证画面读原旁白。
- 旧香港奖励/退出处，进入第一张合影后的迪士尼新增段。
- 旧船座位入口先走新登船路线；旧机场出口入口先走新安检路线。
- 已进入 call、offer、photo 等活动的旧存档继续同一活动。姓名、guest、materials、sceneMaterials 均保留。未知签名返回 false 且不修改存档，由既有 Player 安全回本场开头。

## 测试结果

`godot/hongyuan/tests/scene_migrations_versions_test.gd`：**119 项 PASS、0 FAIL、0 Script Error**，日志 `scene-migrations-versions.log`。覆盖原基线与 042c367、59 个旧拍的安全目的地、不能串游戏、未知签名不修改数据、姓名和信物保留；通过 JSON 往返与实际 runner.restore 验证 call 当前第 5 行、offer letter 与有效滚动范围、photo 双人归位并重抓。退出时存在 ObjectDB 清理警告，已原样保留日志，不把它称为全日志零警告。

旧 `scene_migrations_test.gd` 曾直接索引所有新场景的历史基线，因新增 chengdu_return 无历史记录而报错。按授权更新测试以跳过没有基线的新场景；保留对未变 beat 的精确位置断言，同时检查相同 game 键、内部状态和位置。复跑结果：**16 项 PASS、0 FAIL、0 Script Error**，日志 `scene-migrations-legacy.log`。

主工位导出开始后，本工位只修改旧测试与这份回执，没有继续修改 production 文件。
