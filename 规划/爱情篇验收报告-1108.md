## 已定位的问题和复现步骤

### 01 · 根目录试玩入口无法提供指定的爱情篇

- **严重程度**　卡死（验收入口）。
- **现象与复现**　在指定分支根目录执行 `/bin/zsh ./手机试玩.command`。它调用 1028 村庄的服务脚本，本次直接输出「本轮Web试玩包尚未完成核验，未开启旧包服务。」没有给出爱情篇地址。
- **证据**　`phone-launcher.log`，以及 `手机试玩.command` 和 `候选/试玩收尾-1028/serve_web.py`。
- **建议修法**　提供独立的爱情篇启动命令，从本分支出包并验证构建身份，再仅在局域网发布。局域网 HTTP 下先用同版整包，分章包的生产测试用 HTTPS。当前分章代码只对开发用 loopback HTTP 开例外。

### 02 · 收件人输入存在平台差异

- **严重程度**　卡死（如果真机点框无反应）。
- **现象与复现**　终章读到写名字后，点输入框，检查 iPhone Safari 是否弹出原生输入对话框，输入两字中文并确认。另测取消后能重开、1 字受拒和 12 字可提交。
- **证据**　`godot/hongyuan/games/finale.gd` 的 `_make_edit`、`_web_name_input`、`_wechat_name_input`。普通触屏网页路径禁用虚拟键盘，当前只接受模拟鼠标松开后调用 `window.prompt`。若平台只送触摸事件，或者浏览器未把延后的回调视作用户手势，会走不到或无法可靠弹框。微信路径桥接为空会静默返回。若微信未回调完成，GDScript 的 `keyboard_open` 会留在打开态。
- **建议修法**　在网页壳原生 DOM 事件中直接聚焦 HTML 输入或调用对话框，结果回传 Godot。若用 Godot 同时受理触摸和模拟鼠标，先做去重。微信桥接增加不可用提示，失败和取消都清理监听与打开态，再允许重试。安卓和微信仍需真机确认。

### 03 · 当前 Web 导出没有爱情篇专属开屏

- **严重程度**　影响体验。
- **现象与复现**　冷启动看首屏。当前「红缘Web」导出配置没有自定义 HTML 壳，现有 `wxgame/splash.js` 在旧村庄 `export-wechat.sh` 的流程里接入。爱情篇的新图是独立美术交付，当前验收提交未接该图。
- **证据**　`godot/export_presets.cfg` 的「红缘Web」、`godot/hongyuan/tools/export_web.py`、`godot/export-wechat.sh`。局域网 HTTP 包在引擎安全检查就拦截。本机回环整包正常冷加载时确实只有 Godot 标志和进度条。见 `web-monolith/startup.png`。
- **建议修法**　在 Web 壳用可单独下载的开屏图，先出画面，再开始引擎和 PCK 下载。游戏名与加载状态在 HTML 叠加，第一帧书桌出现后收起。微信按爱情篇入口单独接入同一资源。

### 04 · 上海车身、静冈路人比例需复核

- **严重程度**　影响体验。
- **现象与复现**　在仓库根目录跑 `python3 godot/hongyuan/tools/check_scale.py --strict`。检查 117 项，报 3 类。上海街景的侧面车被换算成约 1.15 米，目标为 1.45 米。尾视素材 `g42_rear_r2.png` 没有登记真实尺寸。静冈一名路人 scale=0.80，低于成人区间。
- **证据**　`scale-strict.log`。尾视项表示校验缺尺寸，不能据此说画面已量出偏差。
- **建议修法**　给车尾素材登记真实尺寸，按同一深度排对齐轮胎和脚点。静冈先核对该路人设定，再使用成年人比例或明确的儿童素材。截同层正位与经过热点的画面复核。

## 测试口径

`run_all.sh` 只报用户列出的 12 项之外的新失败。Mac 的 timeout 兼容层另存每个进程的退出码，避免把没有打印 FAIL 的超时计为通过。真机冷启动按文件记录请求大小、耗时、状态、控制台和首次可见画面；Mac 模拟结果单列。清档用本轮局域网测试来源验证，先留下一个新进度，再访问 `?new=1`，核对首章、地址栏和之后普通刷新是否续档。


## Web 包体积与入口实测

局域网整包取自本验收提交，复用了经源文件和导入参数校验一致的既有缓存，剩余贴图以临时无损 PNG 导入。由此得到的数字只对应本次验收包。

- 局域网整包 `.pck` 467,474,352 字节，`.wasm` 39,514,754 字节，两项合计 506,989,106 字节。
- 本机分章版本的启动 PCK 为 5,752,364 字节，WASM 同为 39,514,754 字节。上海、成都、来电、静冈、海南、香港、终章各包分别为 8,797,276、4,191,188、9,192,132、20,283,012、8,121,744、19,747,096、13,248,268 字节。
- 独立的共同媒体组 `love-media` 175,225,336 字节。本机连续浏览器测试在序章第四屏后开始获取共同媒体。在 40 秒测试观察窗口结束时仍有多个 HTTP 200 请求，属于测试时限和资源等待，未确认游戏发生下载超时。
- 局域网 HTTP 在 Mac 复现了 Godot 的 “Secure Context” 硬拦截。复现为打开验收地址，等待页面显示红框错误。HTML、JS 与图标有请求，服务器未收到该轮 PCK 和 WASM 请求。建议给 iPhone 使用受信任的 HTTPS 并保留分章入口，避免整包阻塞。见 `web/startup.png`、`lan-server.log`、`split-content-sizes.json`。没有 iPhone 上的对应性能数据前，不以 Mac 数字代替。
- Web GDScript 请求超时设为 90 秒，微信桥接为 85 秒。建议把序章和上海的首段必需媒体移入启动或各自章节组，后续按章加载，避免第一道过渡等待共用媒体组。资源下载失败时需核对重试、回书桌和续玩三条路径。

- **严重程度**　影响体验。
- **复现与证据**　静冈切换到上船后停在初始位置。见 `scenes/201_shizuoka_pier_09_go.png`，两位路人在主角脚点附近穿过并遮住主角外轮廓，坡道热点仍可见。

### 07 · 文昌烟花自动推进

- **严重程度**　影响体验。
- **复现与证据**　完成万宁套圈，走到文昌岸边，读完对白后松手。浏览器走查在 91.8 秒记录等待，在 100.0 秒记录凝蜡信物，间隔约 8.2 秒。见 `browser-story-continue2/events.jsonl`，对应 `hainan/wanning_13_wait` 至 `hainan/wanning_15_material`。该区间没有玩家输入。
- **建议修法**　按补充任务书给玩家一个实际放烟花动作。保留岸边连续演出，把触点与发射位置关联，让玩家有明确输入与反馈。

### 08 · 宴会厅切村子后报已释放回调

- **严重程度**　影响体验。
- **复现与证据**　正常结束爱情篇，选择入席，按「直接入席」，再点「去村子入住」。浏览器日志先收到 `WORLD_READY route=village`，约三秒后有六条 `Lambda capture ... was freed` 错误，另有六行堆栈。见 `browser-story-continue2/events.jsonl` 220.444–225.461 秒和该轮 `report.json`。本次随后可以返回婚宴并刷新，宾客名与形象仍在。
- **建议修法**　定位离开宴会厅后仍运行的定时器、信号和动画回调。将它们绑定到场景节点生命周期，切换前取消旧回调，再连跑婚宴→村子→返回及刷新，确认控制台不再报错。当前日志还未定位到具体回调。

## Godot 用例新增失败

未发现已知旧失败名单以外的产品断言失败。非旧失败共 18 项，前段由 `run_all.sh` 取得，后段在原套件等待已知旧超时期间单独补跑。婚宴桥接脚本规定 userdata 路径必须包含 `world-bridge-tests`，普通目录会拒绝运行并返回 2。以专用隔离存档重跑后，入口、宾客身份、直接入席、村庄往返和重启恢复均通过，`WORLD_BRIDGE_FAILURES 0`。见 `run_all.log`、`raw-tests/exit.tsv`、`remaining-tests/`、`world-bridge-isolated.log`。原套件的旧超时不计作新增失败。

## 需要阿鱼真机确认

Mac 已连到 iPhone 的 USB 网页检查服务。局域网 HTTP 的验收包在本机已复现安全上下文拦截，尚未采到 iPhone 的游戏页请求与控制台。用受信任 HTTPS 发布同版后，再按以下顺序取证。

1. Safari 开独立测试标签，从 Mac 的开发菜单选中该页并启用保留日志。禁用缓存后加载，录每个资源、状态和首次交互时间，确认进度条上方是否出现新版开屏。
2. 到终章「写下名字」，点输入框。确认是否弹原生对话框，取消后再打开，提交「小林」并确认下一步。安卓 Chrome、微信小游戏用相同步骤独立验证。
3. 序章推进一屏后，在相同测试来源加 `?new=1`。核对进度回到第一屏、参数移除，再推进并普通刷新。用已知测试档检查成功与保留两种状态。
4. 正常从首屏走到婚宴迎宾院、喷泉广场，顺带确认换图后的江边卡片和分屏对白是否遮人。
