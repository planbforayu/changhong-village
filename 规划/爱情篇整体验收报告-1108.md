# 爱情篇整体验收报告（1108）

## 结论

**本次验收不通过，暂不建议把当前 Web 包交给安卓玩家。** 最新验收分支为 `claude/art-integration-1108`，commit `05dc6a1be625b93a15b728ba81462ccc6ebce7c9`，使用 Godot `4.7.2.stable.official.ed1daf0bf`。没有改游戏代码。

最严重的问题是首载文件过大：项目默认 `bundled` Web 导出产生 **430,209,344 B 的 `index.pck`**，另需 **39,514,754 B 的 WebAssembly**。包含网页、脚本、工作线程和默认加载图后，初次加载核心文件约 **470,041,348 B（470.0 MB）**。启用章节分包后，首进上海仍会依次取得 **139,116,948 B 的 `love-media`** 和 **8,790,144 B 的上海包**，加上引擎和启动包，至少 **193,423,381 B（193.4 MB）**。这是导出文件的原始字节数，不代表已在手机上量到的实际网络时间；但足以解释安卓首次加载很慢或失败的风险。

## 三个优先问题

### 1. 首次加载慢、安卓失败风险：P0，发布阻断

**现象与复现**

- 默认 `godot/hongyuan/content_manifest.json` 是 `mode: bundled`；`content_packs.gd` 在 bundled 模式直接跳过网络请求。因此普通未分包导出必须在页面初载下载整个 `index.pck`。
- 按当前默认 Web 预设导出，`index.pck` 为 430.2 MB，WASM 为 39.5 MB，核心初载约 470.0 MB。测量见[默认整包大小](验收证据-爱情篇-1108/export_sizes_bundled.json)。
- 使用分包导出后，章节切换时 `player.gd` 调用 `Packs.ensure(["love-media", chapter])`。对上海，分包测量为 `love-media` 139.1 MB（10 个包）+ `shanghai` 8.8 MB。两组均由 `ensure_groups()` 顺序等待；不是进入上海时只下载上海小包。见[分包体积](验收证据-爱情篇-1108/export_sizes_remote.json)。
- 当前加载器单包超时 90 秒、15 秒无进度就中断；微信桥每个文件设置 85 秒超时。共享素材包会逐个请求，多个包的时间可累计。失败后会显示“这段回忆还没有加载好”，提供“重试”和“回到书桌”，不会让玩家无反馈地继续。

**建议**

1. 先修复标准网页导出，使其能生成有效包；将默认发布流水线切到经过验证的分包产物，禁止把 430 MB 整包误发布。
2. 把 139 MB 的 `love-media` 拆回按章节/入口实际需要的资源组，并避免进入上海时串行下载十个共享包；再压缩 39.5 MB 的 WASM/首包资源。
3. 发布前设置首包、首次可玩和章节下载体积门槛，并在安卓蜂窝网与弱网下实测。

### 2. 收件人键盘：普通手机网页已有 prompt 路径，安卓尚未实测；微信路径仍有静默失败

**最新代码状态**

`finale.gd` 已按你说明改为普通手机网页调用浏览器 `window.prompt`，所以不能再按旧版本断言“网页没有键盘”。这条分支根据 `DisplayServer.is_touchscreen_available()` 选择，处理器只接收 `InputEventMouseButton`；项目设置开启了 touch-to-mouse 模拟。当前环境没有 Android 真机，无法确认安卓浏览器的触摸事件、浏览器 prompt 手势权限及中文输入实际是否正常。

微信小游戏走另一条 `wx.showKeyboard` 路径。若 `hongyuanContent` 桥接对象为空，处理器直接返回，没有提示或替代输入；打开成功后的 `keyboard_open` 依赖完成/失败回调复位。JS 的 `showKeyboard` 失败回调会完成并回传当前草稿，但桥接缺失仍会让玩家点了没有反应。

**建议与真机步骤**

安卓 Chrome 和微信小游戏分别测试：从终章进入收件人填写，点输入框，输入两个以上中文字符，提交；再取消一次并重新打开。记录机型、Android/浏览器或微信版本、是否弹出系统键盘/浏览器对话框、取消后能否重开。安卓网页如无弹窗，重点检查触摸是否被识别为鼠标释放及 `window.prompt` 是否被浏览器策略拦截；微信路径补桥接缺失提示和可恢复的重试入口。

### 3. 没有爱情篇开屏页：P1，体验问题确认

爱情篇项目默认入口是 `hongyuan/boot.tscn`，`boot.gd` 随即切换到爱情篇播放器；它没有进入 `scripts/main.gd` 所挂的 `title_screen.gd`。微信加载脚本 `wxgame/splash.js` 只在 `export-wechat.sh` 中复制并补丁注入；标准 `hongyuan/tools/export_web.py` 不做这件事。

Godot Web 模板当前展示的是黑底 Godot 标志及默认进度层，不是爱情篇画面。导出内的 [默认加载图证据](验收证据-爱情篇-1108/default_web_splash.png)可见 Godot logo。新画的开屏图已经提交到 `art/love-1108`，但尚未接入 Web/boot 页面，需由后续集成工作完成接线。

## 导出阻断问题：P0

直接运行标准 `hongyuan/tools/export_web.py` 时，Godot 报告缺少 `lounge_09.dialogue`、`boatman_1.dialogue` 的导入资源，导出后脚本继续找不到 `index.js` 并失败。原因是该导出上下文没有启用 Dialogue Manager 导入插件；我在验收副本里临时启用插件后，才得到上面的整包和分包数据，未把此临时设置提交。复现摘要见[标准导出错误](验收证据-爱情篇-1108/standard_web_export_error.txt)。建议 Web 导出显式启用所需导入插件，并把“目标文件存在、体积清单生成”设成发布前必过条件。

## 需要阿鱼真机确认

1. Android Chrome 清除站点数据后打开网页，记录首次打开到序章可操作、首次进入上海可操作分别花多久，并记录网络面板请求字节；当前测得的 470.0 MB/193.4 MB 是导出原始字节预算。
2. 在终章收件人页分别测中文输入、取消后重新打开、横竖屏或软键盘遮挡输入框情况。
3. 微信小游戏按相同步骤测 `wx.showKeyboard`；同时观察空桥接/资源超时后是否出现可理解的提示。
4. 首次加载期间确认展示爱情篇画面，而不是 Godot 默认 logo/进度界面。
